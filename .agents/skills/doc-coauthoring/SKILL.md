# Coauthor a focused document

Use supplied context and existing decisions first. Identify the reader, decision or
job the document supports, and unresolved material questions. Infer obvious answers;
ask only for information that changes the result.

Draft the smallest complete document that supports the reader. Distinguish accepted
requirements, recommendations, and open questions. Keep one canonical statement of
each decision and link it instead of copying it into multiple documents.

Iterate on specific feedback. No fixed question count, option quota, section approval,
or obligatory workshop. For routine reference edits use documentation-writer directly.

Review whether a reader can act using only the document. For a consequential ambiguous
spec, a focused independent reader check may be useful; it is not required for every
section or a reason to reopen accepted scope. Record actual gaps and fix them.

Save repository documentation in its established location. The ArcNexus charter is
`docs/charter.md`; the local founding conversation is historical context, not a
replacement for a tracked, self-contained specification.
